==============================================================================
THE ADVANCED FEATURES
==============================================================================

There are fourteen now: the twelve original ones, automatic defensive ECM, and
offensive ECM in two modes. All of them live in the game's own right-click
menu, each in the section a player would look in first - not stacked into one
submenu. There is no mod window and no hotkey.

  Radars, air/surface search only, active sonar, towed array, EMCON profiles
      Where it appears: Sensors

  Radar blink, auto-ARM shutoff, defensive ECM, offensive ECM, commercial disguise
      Where it appears: Sensors (they are emission decisions)

  ECM cones on the map
      Where it appears: Not a menu entry - drawn over the map whenever a set
        is aimed

  Salvo deconfliction
      Where it appears: Engage (it is about who may fire, and when)

  Action stations, cold cruise, crew fatigue
      Where it appears: Rules of engagement

  Sprint and drift, turn the screen onto the threat
      Where it appears: Formation

  Helicopter ladder / square / sector
      Where it appears: Air operations

  Local control, replenish alongside
      Where it appears: Damage control (replenishment falls back to
        logistics)

  Breakaway with chaff and hard rudder
      Where it appears: Top level, one click - it is the emergency button

Sections are found by keyword at runtime, because the game's exact menu labels
are not in the API dump. If a section is missing in your build, the entry
moves up to Orders rather than disappearing, and capabilities.txt lists the
section labels that were actually found - so the routing can be corrected from
a single log rather than a guess. This document says what each one does, which
game member it drives, and - where it matters - what it honestly cannot do.

HOW TO TEST THEM
----------------

Right-click one of your ships -> Orders. You should see Weapon hatches and the
feature entries, spread across Sensors, Engage, Rules of engagement,
Formation, Air operations, Damage control and Logistics. Each toggle states
its own state in the label ("Radar blink: on - click to stop"), and each
action reports through the game's order-feedback text as well as
seapoweradvanced.log.

Anything that goes wrong is written down. capabilities.txt in the mod folder
lists every lever the mod found in your build of the game, and ecm-report.txt
lists every ECM member and type it found.

------------------------------------------------------------------------------

1. RADAR BLINK CYCLING  -  SENSORS AND EMCON
--------------------------------------------

Switches a radar on for a few seconds, then off again, on a timer. A real ship
does this so a passive anti-radiation seeker has to track an intermittent,
moving source instead of a steady beacon.

You choose which set. The entry is a submenu:

  Air search radar
      What cycles: The air-search set only
      Why you would pick it: This is the set an anti-radiation missile homes
        on

  Surface search radar
      What cycles: The surface-search set only
      Why you would pick it: Still finds ships, far harder to home on

  Both radars
      What cycles: Both, on one timer
      Why you would pick it: Two intermittent emissions, one control

A hull with no radar is not offered the entry. Stopping puts every set back
exactly as it was found - if the radar was off before, it stays off.

  Interval
      EnableSurfaceSearchRadars(bool,bool) /
        DisableSurfaceSearchRadars(bool), state read from
        IsSurfaceSearchRadarsOn: Features/BlinkSeconds, default 6 s

  Reversible
      EnableSurfaceSearchRadars(bool,bool) /
        DisableSurfaceSearchRadars(bool), state read from
        IsSurfaceSearchRadarsOn: Yes - stopping puts each radar back exactly
        as it was found

2. AUTO-ARM SHUTOFF  -  COUNTERMEASURES
---------------------------------------

When a weapon is tracked against the ship, the radars go dark for eight
seconds, then come back. This is what an anti-radiation missile forces a ship
to do, and it costs the ship its own air picture, which is why it is off by
default and opt-in per ship.

  Sensors used
      DisableAllRadars() / EnableAllRadars(bool): _incomingWeapons,
        _dangerousMissiles, ThreateningMissile (read by reflection: you cannot
        call the get_ accessor, that is CS0571)

  Honest limit
      DisableAllRadars() / EnableAllRadars(bool): The game does not label a
        missile as anti-radiation in any readable member, so any inbound
        weapon goes dark. That is conservative on purpose.

  With defensive ECM
      DisableAllRadars() / EnableAllRadars(bool): Defensive ECM wins while
        it is jamming: a jammer cannot hold a lock with the radar dark. The
        two features do not fight each other on the same ship.

2B. AUTOMATIC DEFENSIVE ECM  -  SENSORS AND EMCON
-------------------------------------------------

Every ship that carries a jammer also defends itself and its formation with
it, without being asked twice. When a vampire - a weapon the game is tracking
against this ship, or against any ship of the task force within 25 nm -
appears, the mod:

  1. puts the air-search radar on. A jammer needs a fire-control quality
     bearing to know where to point, and that bearing comes from radiating.
     This is the price, and it is not optional: while the jammer works, the
     ship is the loudest thing in the water. It is the same trade a real
     commanding officer makes, and it is why the feature is armed deliberately
     rather than always on.
  2. hands the missile itself to the jammer as its target, so the set is
     pointing at the seeker rather than at a bearing the mod computed.
  3. raises power or mode, where this build exposes a control whose units the
     mod can trust.
  4. holds the lock - the target is re-pointed four times a second for as long
     as the missile is tracked, so a lock that the game clears is immediately
     re-established.

When the sky has been clear for six seconds it stands down, stops jamming, and
puts the air-search radar back exactly as it was found.

  Sensors
      The game's own ECM switch, ECM target member and power/mode member -
        all found at runtime by name, never guessed (see
        Interop/EcmControl.cs): Air-search radar on for the duration; that is
        the deliberate cost

  Range
      The game's own ECM switch, ECM target member and power/mode member -
        all found at runtime by name, never guessed (see
        Interop/EcmControl.cs): Defends the ship and any task-force ship
        within 25 nm of it

  Honest limit
      The game's own ECM switch, ECM target member and power/mode member -
        all found at runtime by name, never guessed (see
        Interop/EcmControl.cs): The mod cannot promise the missile misses. It
        points the game's jammer at the game's missile and keeps it there;
        whether the seeker breaks lock is the simulation's answer. "Almost
        impossible to resist" is not something a mod can guarantee without
        knowing the game's jamming model, and this one does not pretend to.

  Honest limit
      The game's own ECM switch, ECM target member and power/mode member -
        all found at runtime by name, never guessed (see
        Interop/EcmControl.cs): If this build names its jammers something the
        scan does not recognise, the feature says so in the menu and writes
        ecm-report.txt listing every ECM-like member it found. That file is
        ground truth from the installed game and is the fastest way to make
        the next build exact.

Which units get which entries

The mod only offers an option to a unit that can carry it out:

  ECM (defensive, offensive, mode and lock)
      Shown for: hulls the game says carry ECM, and surface hulls where it
        does not say. Never on submarines

  Active sonar, towed array
      Shown for: hulls that report the fit, or where the game does not
        report one

  Helicopter search patterns
      Shown for: hulls with a flight deck or hangar, or surface hulls where
        the game does not say

  Replenish alongside
      Shown for: surface hulls

  Lock with ECM on a contact
      Shown for: hostile and neutral contacts, when one of your ships with
        ECM is in range. Nothing else is added to a contact's menu

  Sensors -> Defensive ECM: off - click to arm automatic jamming
      What it does: Arms this ship

  Sensors -> Defensive ECM for the whole task force
      What it does: Arms every ship under command

  Sensors -> ECM: what this build exposes
      What it does: Writes ecm-report.txt again on demand

2C. OFFENSIVE ECM, TWO MODES  -  SENSORS AND EMCON
--------------------------------------------------

The ship's jammer, used deliberately. There are two modes and the default is
the one that changes nothing.

Standard (default)

The game's own ECM behaviour. The mod does not touch the set, does not radiate
for it, and switches back to this the moment you pick it - which also releases
any lock it was holding. If you never open this menu, nothing about your
jamming changes.

Signature lock

Two ways in, and both end in the same place:

  * Right-click the enemy contact itself -> Lock with ECM. That is the only
    entry the mod adds to a contact's menu; the game's own identification
    entries (mark hostile/neutral, request identify) are untouched. The mod
    picks whichever of your ships with ECM is nearest and inside range, and
    names it in the label, so you do not have to work out which hull carries
    the jammer. If nothing of yours is in range, the entry is not added at
    all.
  * Right-click your own ship -> Sensors -> Offensive ECM lock and pick a
    contact from the list (the contacts the task force holds, nearest first,
    max 40 nm for ships and 90 nm for aircraft).

Aircraft and helicopters

Planes can be locked too, and they are the case the range matters for. A
jammer has to be inside the other radar's horizon, and the radio horizon is
not the same for a masthead as for a wing:

  Ship or sea-skimming missile
      Reach: JamRangeNm, 40 nm
      Why: Both ends are a few metres above the water

  Aircraft or helicopter
      Reach: JamAirRangeNm, 90 nm
      Why: A masthead sees 4.5 nm; an aircraft at 15,000 ft sees 65 nm on
        its own, so the pair see each other at about 70 nm and further for a
        high patrol

Jamming an aircraft is not the same as jamming a ship, and the mod says so
rather than pretending otherwise:

  * it carries one radar, not a ship's families. Radar off means blind, and
    its crew can put it back up between assertions like anyone else's.
  * its receiver cannot be jammed off at all - a passive set has nothing to
    switch down - so the report says that instead of claiming a clean sweep.
  * the entry names the type: Lock E-2C Hawkeye - aircraft (68 nm).

The contact picture is now the force's, not one ship's: an aircraft a picket
detected can be jammed by whichever ship has the set nearest it. The contact
lists themselves are looked for - any member on a unit whose name says it
holds contacts, threats, tracks or detections - because an air plot is not
always kept where the surface one is. offensive-ecm.txt records which lists
were read, so the next build can be exact.

Either way the mod then:

  1. reads that contact's sensor fit - which radar families it has and whether
     each is up, whether it has a towed array or active sonar, whether it is
     running ESM or its own jammer, and what its hull signature reads as. This
     read is the lock: a jammer that has not identified what the other ship is
     radiating with has nothing to aim at. Locking does not transmit. The beam
     appears on the map and the target carries on as it was.
  2. Jam now - transmit on the lock is a second, manual order. Only then are
     every one of those families switched off on that contact, and only that
     contact.
  3. holds them down - re-asserted ten times a second while transmitting,
     because the target's crew can switch a set back on in between. Sustained
     suppression, not a one-off toggle.
  4. Jamming: on - click to stop transmitting stops the jam and keeps the
     lock, so it can be resumed. Nothing is put back on the radar front,
     because this mode never touched it.
  5. stands the lock down when the target is sunk, runs beyond range, you
     release it, or you go back to standard.

  Reads
      The target's own switches: DisableAllRadars(), DisableAirSearchRadars,
        DisableSurfaceSearchRadars, TowedSonarsSetActive(false),
        DisableActiveSonars, plus any ESM / jammer switch it exposes: Its
        radiator state (IsAirSearchRadarsOn, IsSurfaceSearchRadarsOn), its
        sensor fit (HasTowedSonar, HasActiveSonar), its hull signature from
        its parameter block

  Range
      The target's own switches: DisableAllRadars(), DisableAirSearchRadars,
        DisableSurfaceSearchRadars, TowedSonarsSetActive(false),
        DisableActiveSonars, plus any ESM / jammer switch it exposes:
        Features/JamRangeNm, default 40 nm against ships;
        Features/JamAirRangeNm, default 90 nm against aircraft

  Cost
      The target's own switches: DisableAllRadars(), DisableAirSearchRadars,
        DisableSurfaceSearchRadars, TowedSonarsSetActive(false),
        DisableActiveSonars, plus any ESM / jammer switch it exposes: None in
        emissions. This mode runs on EMCON: it never switches the attacking
        ship's radar on, so the jammer gives away nothing while it works. (The
        defensive feature does need air search - it is locking onto a missile,
        not a contact.)

  Result you will see
      The target's own switches: DisableAllRadars(), DisableAirSearchRadars,
        DisableSurfaceSearchRadars, TowedSonarsSetActive(false),
        DisableActiveSonars, plus any ESM / jammer switch it exposes: every
        sensor off, or NOT all sensors off - <sensor> would not switch off on
        this build. The second is not a bug in the lock: it means the game
        gives no way to reach that one sensor family, so it is still working.
        The menu names it and offensive-ecm.txt lists it as STILL. The mod
        does not edit the target's picture to hide that.

  Honest limit
      The target's own switches: DisableAllRadars(), DisableAirSearchRadars,
        DisableSurfaceSearchRadars, TowedSonarsSetActive(false),
        DisableActiveSonars, plus any ESM / jammer switch it exposes: The
        effect lasts as long as the lock is held. It is not a permanent state
        change to the other ship's data, and it stops the moment the lock is
        released - which is why the mod re-asserts rather than setting it
        once.

offensive-ecm.txt in the mod folder records every lock, appended rather than
overwritten: which kind of target it was, which contact lists the picture was
read from, the signatures read off the target, what was silenced, what was
not, and the jammer path used. It is the file to send if the target does not
go quiet when it should - and the file to send if an aircraft does not appear
in the lock list at all.

2D. THE ECM CONES ON THE MAP  -  SENSORS AND EMCON
--------------------------------------------------

A jammer is directional and a menu cannot show you which way it is pointing,
so the mod draws it:

  Offensive set, locked, not transmitting
      What you see: a long, narrow cyan beam from the jammer to the ship it
        is locked on, thin and dim

  Offensive set, jamming
      What you see: the same beam, bright and thicker, with ECM JAMMING on
        the far end

  Defensive set, engaged
      What you see: an amber beam to the missile it is tracking, with a
        marker on the missile

  A ship with ECM selected, nothing aimed
      What you see: a small cyan box on the ship and ECM ready

The beams are deliberately long and narrow - they are bearings, not areas, and
a cone wide enough to look like a search fan would be telling you something
that is not true.

  Where the ends come from
      IMGUI, the same way the civilian traffic panel is - no assets, no
        XAML: Interop/MapProjection.cs: the game's own GeoPosition-to-world
        conversion if one exists, otherwise the unit's Unity transform,
        projected through the active camera

  If neither exists
      IMGUI, the same way the civilian traffic panel is - no assets, no
        XAML: nothing is drawn, one line appears at the bottom of the screen
        saying so, and ecm-cone.txt records exactly what was looked for. A
        cone in the wrong place would be worse than none

  Setting
      IMGUI, the same way the civilian traffic panel is - no assets, no
        XAML: Features/ShowEcmCone, default true

  Follows the selected unit
      IMGUI, the same way the civilian traffic panel is - no assets, no
        XAML: the game's own selection member if the mod can find one,
        otherwise the unit whose right-click menu you opened last

If the cones do not appear, ecm-cone.txt in the mod folder says which of the
two projection routes was tried and what the camera was - that file is the
thing to send.

2E. CIVILIAN TRAFFIC  -  CIVILIAN TRAFFIC IN THE RIGHT-CLICK MENU
-----------------------------------------------------------------

Right-click any unit in the mission editor -> Civilian traffic. That is the
whole way in: the game's own menu, the same one every other feature in this
mod lives in, so it works with a mouse and looks like the rest of the game.

    Civilian traffic  >
        Zone: none - draw one or use the map area
        Draw a zone on the map
        Use the map area around your units
        Clear the zone
        Ships at a time: 2-6 - click to change
        Aircraft at a time: 0-2 - click to change
        Spawn traffic now
        Remove generated traffic
        Last: nothing spawned yet this session
        Check setup - writes traffic-report.txt

Why it is not a floating window any more: the panel drew, but the game's own
interface layer swallowed the mouse, so no button in it could be clicked.
Every function is a menu entry now, and the two things a menu cannot do are
handled rather than left out:

  take typed numbers
      So...: the counts cycle through presets when clicked: ships none ->
        1-2 -> 2-4 -> 2-6 -> 4-10 -> 8-20 -> 16-40, aircraft none -> 1-2 ->
        2-4 -> 4-8 -> 8-16

  pop up a message
      So...: every action reports twice: the game's own on-screen order
        feedback on the unit you clicked, and the Last: line at the bottom of
        the submenu, which is still there next time you open it

The order of a first run: Use the map area around your units (or Draw a zone
on the map), set the two counts, Spawn traffic now, then save the mission.

The F8 panel still exists if you want it, but nothing depends on it any more.

Two ways to make a zone

  Draw a zone on the map
      What it does: Hands the mouse to the game's own polygon tool. Left-
        click points, then Finish the zone (the entry changes to that while
        drawing) or middle-click
      When to use it: When you want a specific stretch of sea

  Use the map area around your units
      What it does: Builds a zone from the sea the mission's units are
        already in: their bounding box plus 30%
      When to use it: When drawing does not work, or you just want traffic
        where the action is

The zone line always says which of the two is in use and how big it is. If
neither exists, Spawn traffic says so instead of doing nothing.

What was wrong, and what was rebuilt

  It was an IMGUI window
      Why it made the feature look dead: The game's own UI layer consumed
        the mouse, so it drew but nothing in it could be clicked
      What it does now: The game's own right-click menu. No separate input
        path to lose

  Four text fields
      Why it made the feature look dead: Typing into IMGUI inside a
        fullscreen game fights the game's own input
      What it does now: Counts cycle through presets on click

  The result was one line, overwritten by the next click
      Why it made the feature look dead: You could not see what had happened
      What it does now: On-screen order feedback plus a Last: line in the
        submenu

  The route list had to be a List<CivilianRoute> exactly
      Why it made the feature look dead: A mission holding any other
        collection type - including the observable collection the game's own
        view models use - was refused with "not a list of routes the mod can
        write to". This is very likely why nothing ever spawned
      What it does now: Any IList is accepted, added to through IList.Add,
        and the count is read back so a list that swallows the add is reported
        as such

  A route needed all forty of CivilianRoute's private fields, or it was thrown away
      Why it made the feature look dead: One renamed optional field - a
        diagnostic counter, a loadout list - discarded every route, and the
        only clue was a "Problems: no field ..." tail
      What it does now: Four essential fields, everything else best-effort.
        The ones this build lacks are named in traffic-report.txt instead of
        failing the route

  Globals._neutralTaskforce had to be non-null before anything happened
      Why it made the feature look dead: In the editor it often is null, so
        the feature refused before it started
      What it does now: The taskforce is looked for, and if none is found
        the route is still created and the report says so

  Nothing checked whether the routes actually landed
      Why it made the feature look dead: "Added 2 lanes" could be printed
        while the list never changed
      What it does now: The report now reads "The list now holds N
        route(s)", and zero added is reported with the reason

If it still does nothing

Press Check setup (in the submenu, or on the F8 panel). traffic-report.txt in
the mod folder lists every prerequisite with an ok or -- mark and the exact
type of the list that was found:

      --   civilian route list   no civilian route list found (see traffic-report.txt)
      ok   civilian route list   MissionEditorViewModel.Mission._civilianRoutes (0 route(s)) [TrulyObservableCollection<CivilianRoute>]

That file, plus the panel's own log line, is everything needed to say which
link is missing.

2F. USING IT WITH THE MULTIPLAYER MOD
-------------------------------------

The multiplayer mod (SeapowerMultiplayer, com.seapowermultiplayer.plugin) is
supported: the mod detects it, works out whether this machine is the host or
the client, and changes what it promises accordingly. It is reached by
reflection, so nothing changes for players who do not have it, and nothing
breaks if it is not installed.

multiplayer.txt in the mod folder says what was found and which rules followed
from it. It is rewritten when a session comes up or ends.

Three of the multiplayer mod's rules matter here:

  It throttles radar switches to one per ship per radar group per 10 seconds, and a throttled switch does not move locally either
      What it does to this mod: Radar blink raises its half-cycle to 12
        seconds in a session, whatever BlinkSeconds says. A six second blink
        would lose every second flip and leave the radar stuck

  The client does not decide its own emissions - the host's radar picture is re-imposed every frame
      What it does to this mod: Radar blink checks each flip four seconds
        later. If the switch did not take, the blink stops itself and says so
        rather than pretending. Auto-ARM and defensive ECM are not offered on
        a client at all, and the menu says why

  Jamming is an order the host runs, not a member write
      What it does to this mod: Offensive ECM on a client sends the game's
        own jam order, which the multiplayer mod forwards. The signature
        lock's switch-off assertion is not attempted from a client: the target
        is simulated on the host, so there is nothing there to switch off

What still works everywhere:

  * Everything on the host, and in single player without a change: this
    machine simulates the world.
  * The ECM cones - they draw from whatever jamming the game reports on this
    machine, including jamming the session replicated in from the other side.
  * The menus, hatches, salvo planner, readiness, formations, helo patterns -
    these go through the game's own orders, which the multiplayer mod already
    forwards.

Two limits worth stating plainly, because a player will otherwise read them as
bugs:

  1. A jam started from a client cannot be stopped from that client. The
     multiplayer mod forwards a jam order but has no "stop jamming" order, so
     the host's jam task runs until it ends by itself. The menu says so when
     you stop it.
  2. Damage, hits and sensor outcomes are the host's. Nothing here claims a
     different result from the one the authoritative machine reached.

3. COMMERCIAL SIGNATURE SPOOFING  -  DECEPTION
----------------------------------------------

The ship stops radiating, drops to a merchant's telegraph setting, and
presents a civilian-looking signature string (MV <hull>).

  Honest limit
      DisableAllRadars(), setEMCON(bool,bool), setTelegraph(int), the
        signature member on the hull's parameters: The mod cannot make an
        enemy's radar read our signature. That needs a patch on the detection
        routine. Treat this as a reduced emission profile, and the log says so
        every time it is used.

4. SALVO DECONFLICTION  -  STRIKE
---------------------------------

Holds every ship but the leader at hold-fire, then releases them one at a time
so the task force's launches arrive as several engagements instead of one.

  Enum values
      SetWeaponStatus(WeaponStatus, bool): Read from WeaponStatus's own
        names at runtime - "hold/tight/safe" and "free/open/engage" - so a
        renamed enum cannot make it set the wrong state

  Spacing
      SetWeaponStatus(WeaponStatus, bool): Features/SalvoSpacingSeconds,
        default 8 s

  Never
      SetWeaponStatus(WeaponStatus, bool): Fires anything. It only decides
        when each ship may fire.

5. BREAKAWAY WITH CHAFF AND HARD RUDDER  -  COUNTERMEASURES
-----------------------------------------------------------

Full ahead, rudder hard over, chaff away, noisemaker - all in one action, at
the moment a missile is actually tracked.

6. DEGRADED LOCAL CONTROL  -  COUNTERMEASURES
---------------------------------------------

Ships the guns and CIWS onto local control for when the fire-control picture
is lost.

  Honest limit
      Any member on the hull whose enum type is named Discipline (the game
        has CiwsDisciplineState), set to the value whose name mentions
        local/manual/autonomous: If this build exposes no such member, the
        menu reports that the game was not told rather than claiming success.

7. COLD CRUISE VS BATTLE STATIONS  -  READINESS
-----------------------------------------------

Closes the ship up: reloads run about 15% faster while held, and the crew
starts to tire.

  Also
      WeaponSystem._remainingReloadTime is shortened on every mount that is
        reloading: SetWeaponStatus(<its own enum>, bool) for the weapons
        posture, reached through WeaponStatusControl

  Honest limit
      WeaponSystem._remainingReloadTime is shortened on every mount that is
        reloading: General quarters is not a game concept - the mod keeps it,
        and expresses it through these two levers.

8. THREAT-AXIS SCREEN REORIENTATION  -  MANOEUVRES
--------------------------------------------------

Finds the nearest tracked threat, computes the bearing to it, and re-stations
the task force onto that axis.

  Reads
      setWaypointTask(GeoPosition, string, <height enum>) on each ship,
        through WaypointControl: _threats, _dangerousMissiles,
        _spottedObjects, getGeoPosition()

  Detail
      setWaypointTask(GeoPosition, string, <height enum>) on each ship,
        through WaypointControl: Bearing is corrected for latitude, so it is
        right in the North Atlantic rather than skewed

9. SPRINT-AND-DRIFT ASW  -  MANOEUVRES
--------------------------------------

Toggles the game's own SprintAndDriftDoctrine, per ship or for the whole task
force at once, and streams the towed array. Reports the ship's real cavitation
threshold from CavitationOnsetKts().

  Why not write it ourselves
      SprintAndDriftDoctrine (ReactiveProperty), TowedSonarsSetActive(bool):
        The behaviour already exists and is already tested by the developers.
        The gap the mod fills is doing it fleet-wide, which the game's UI does
        not offer

10. HELICOPTER SEARCH PATTERNS  -  AIR OPERATIONS
-------------------------------------------------

Ladder, expanding square, or sector search. Launches an ASW helicopter if one
is on deck and flies the pattern; if one is already airborne, it just flies
it.

  Enum values
      FlightDeckHasUnit(...), FlightDeckLaunchUnit(...),
        setWaypointTask(...) - all through FlightDeckControl and
        WaypointControl: UnitRoles and MissionType are never named in code.
        The methods are found by name and their arguments are built from their
        own signatures; the role is picked by matching names like ASW, and the
        launch arguments are written to the log

  Honest limit
      FlightDeckHasUnit(...), FlightDeckLaunchUnit(...),
        setWaypointTask(...) - all through FlightDeckControl and
        WaypointControl: If this build's flight-deck call has a shape the mod
        cannot fill, the menu says so and logs the signature instead of
        guessing at it

  Honest limit
      FlightDeckHasUnit(...), FlightDeckLaunchUnit(...),
        setWaypointTask(...) - all through FlightDeckControl and
        WaypointControl: Launch is asynchronous, so the pattern is queued and
        flown once the aircraft appears - the log says "launching" rather than
        pretending it already flew

11. FUNCTIONAL UNDERWAY REPLENISHMENT  -  LOGISTICS
---------------------------------------------------

Takes on ammunition from a supply ship within 2 nm.

  Supply ships found by
      RearmAll(bool), ReplenishAmmo(float,float),
        ReplenishAccountableAmmo(float, Dictionary): Name containing supply /
        oiler / replenish / AOE / AOR / tanker

  Honest limit
      RearmAll(bool), ReplenishAmmo(float,float),
        ReplenishAccountableAmmo(float, Dictionary): Fuel is not transferred -
        this game has no fuel-transfer-at-sea member the mod can find, so only
        ammunition moves, and the log says so

12. BATTLE STATIONS FATIGUE  -  READINESS
-----------------------------------------

Fatigue accumulates while the ship is at action stations: 15 minutes of
general quarters makes a crew fully tired, and a tired crew gives back up to
25% of the reload saving. Standing down recovers more slowly than tiring, so
there is a real cost to leaving the fleet closed up all mission.

  Shown
      The same _remainingReloadTime shave, with the penalty subtracted: The
        current state and fatigue percentage in the Readiness submenu

  Honest limit
      The same _remainingReloadTime shave, with the penalty subtracted: Crew
        fatigue is entirely the mod's model. The game has crew skill, not crew
        tiredness.

SETTINGS
--------

BepInEx/config/io.github.bomberdeer22.seapoweradvanced.cfg, section Features:

  Enabled
      Default: true
      Meaning: Add the eight submenus at all

  BlinkSeconds
      Default: 6
      Meaning: Seconds between radar blink flips (raised to 12 in a
        multiplayer session)

  SalvoSpacingSeconds
      Default: 8
      Meaning: Seconds between ships released in a salvo

  JamRangeNm
      Default: 40
      Meaning: Reach of the focused offensive jammer against a ship

  JamAirRangeNm
      Default: 90
      Meaning: Reach against an aircraft or helicopter - both ends are high
        above the radio horizon

  ShowEcmCone
      Default: true
      Meaning: Draw the ECM cones on the map

WHAT TO SEND BACK IF SOMETHING MISBEHAVES
-----------------------------------------

seapoweradvanced.log (mod folder), capabilities.txt and ecm-report.txt (same
folder). The log names every feature and its result per ship, so a single
failed action is easy to find; the two report files say what the game actually
exposes.

In a multiplayer session, add multiplayer.txt: it names the multiplayer mod's
version, which side of the session this machine is on, and every rule that
followed from it.
