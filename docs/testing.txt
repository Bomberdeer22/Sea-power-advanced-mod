==============================================================================
TEST PLAN
==============================================================================

Run this once per game version, and after any change to HatchControl,
HatchMenu or the feature menus.

Version under test: 0.22.1. Mod id io.github.bomberdeer22.seapoweradvanced.

Read the log, do not guess. Everything below is confirmed by two files:

  BepInEx\LogOutput.log
      What it proves: BepInEx listed the plugin, Harmony patched the game.

  BepInEx\plugins\SeaPowerAdvanced\seapoweradvanced.log
      What it proves: The mod's own log. If this file exists, the code ran.

If seapoweradvanced.log is missing, nothing else in this plan can pass  -
stop and send SeaPowerAdvanced-diagnose.txt (from diagnose.cmd).

0. BEFORE THE FIRST TEST
------------------------

  * [ ] check-source.cmd says PASS. It costs a second and catches the mistakes
    that otherwise show up as CS0246/CS0103 two minutes into a build: a
    missing using, a member that does not exist, and a name used outside the
    method that declares it. build.cmd runs the same check as step [4/6]; it
    never blocks the build.

  * [ ] BepInEx + the Anchor Chain preloader in the game folder (run build.cmd
    once and it puts them there); the game does not say "The Anchor Chain
    preloader is not running!"
  * [ ] SeaPowerAdvanced.dll + _info.ini in BepInEx\plugins\SeaPowerAdvanced\
    (written by build.cmd, step [install])
  * [ ] No leftover copy in Sea Power_Data\StreamingAssets\SeaPowerAdvanced\
    -  a double install loads every patch twice
  * [ ] Game fully restarted after the build (code loads once per launch)
  * [ ] LogOutput.log open in a second window

1. LOAD
-------

In LogOutput.log, BepInEx's own banner should appear:

  * [ ] Loading [Sea Power Advanced 0.20.0]

Then the mod's own startup lines:

  * [ ] Sea Power Advanced: ================ Sea Power Advanced 0.20.0
    ================
  * [ ] Sea Power Advanced: Entry point:  BepInEx plugin
  * [ ] Sea Power Advanced: Settings: enabled=True includeGuns=False ...
  * [ ] Sea Power Advanced: Patched MapUnitViewModel.GetContextMenuItems.
  * [ ] Sea Power Advanced: Context menu patch is live (...)
  * [ ] Sea Power Advanced: Ready. Right-click a ship > Orders > Weapon
    hatches.
  * [ ] No Could not patch, no Startup failed

If Entry point: says AnchorChain mod, the DLL is being loaded from
StreamingAssets  -  that is the double-install case; remove that folder.

Anchor Chain's Workshop copy is optional: without it the build produces the
BepInEx-only plugin and the startup line reads Anchor Chain not installed -
building the BepInEx-only plugin. This is fine. Builds with Anchor Chain
installed also compile an AnchorChain mod entry point, which is unused on the
BepInEx route.

7B. POINTING A MISSILE AT THE WATER (DEFENSIVE ECM)
---------------------------------------------------

  * [ ] Arm a ship with a jammer: Sensors -> Defensive ECM: off - click to arm
    automatic jamming
  * [ ] The entry reads armed, waiting for a vampire and names what the dive
    has done
  * [ ] Fire a missile at that ship and let it cross 10 nm: the log shows
    Defensive ECM: <ship> is flying <missile> down - height ... m, nose N deg
    down, ... u/s, once
  * [ ] Watch it descend and keep flying. It must not stop in mid-air, must
    not spin, must not explode, and must not jump straight to the water
  * [ ] Its nose pitches over and stops at 90 degrees - it does not keep
    turning past straight down
  * [ ] It reaches the water and disappears: taken by the game at the
    waterline. That is the game's own water-dip removal, not the mod deleting
    anything
  * [ ] The ship is not hit
  * [ ] No exception in LogOutput.log - in particular none in
    GameMain.FixedUpdate, and no "Repeated Exceptions detected" warning. If
    one appears, set Features/EcmDiveNm to 0, restart, and send ecm-dive.txt
    and LogOutput.log
  * [ ] ecm-dive.txt names the weapon type's guidance link, loss clock,
    velocity vector, height member and scene object, and prints its whole
    member list
  * [ ] If the missile is held at a fixed height instead of reaching the
    water, ecm-dive.txt says FLOOR <N> m - that number is the skimming floor,
    and the file is what the next fix is written from
  * [ ] If it says the missile is not moving, the game has stopped integrating
    it: send the file, that is the 0.20.0 failure mode reappearing
  * [ ] Set EcmDiveNm to 0 and restart: missiles are jammed but never dived
  * [ ] Disarm defensive ECM and repeat: the missile hits as before, so the
    arming is the difference
  * [ ] Fire a gun at the same ship with defensive ECM armed: the shell still
    hits - stated limit
  * [ ] Channels: fire a four-missile salvo at one armed ship. Three are flown
    down, then the log warns has all 3 guidance channel(s) committed - the
    rest of this salvo is not being decoyed, and the rest hit. The menu entry
    shows 1/2 channels while it is working
  * [ ] Interval: the next missile's descent does not start until two seconds
    after the one before. Raise Features/EcmDiveIntervalSeconds to 12 and a
    two-missile salvo stops being stoppable
  * [ ] Reaction: a missile crossing 10 nm is not dived for about a second;
    the log says designating - the descent starts in 0.9 s first. Set
    EcmDiveReactionSeconds to 8 and the dive starts much later
  * [ ] Seeker filter: fire an infrared or anti-radiation missile at the same
    ship. It is not dived - the log says left a missile alone because of its
    seeker - IRHoming seeker - radio jamming cannot blind that - and ecm-
    dive.txt lists the seeker type it read. Set EcmDiveRadarSeekersOnly to
    false and it is dived again
  * [ ] ecm-dive.txt prints a seeker line per weapon type, and the totals
    count left alone because their seeker is not radar
  * [ ] In a session as a client: defensive ECM is not offered, with the host-
    simulates-weapons reason
  * [ ] A busy sky with many missiles does not flood the log - a handful of
    lines per ship at most

  * [ ] seapoweradvanced.log gains one line: Multiplayer: no multiplayer mod
    or Multiplayer: multimod <version>, installed, no session up
  * [ ] Start hosting, open a mission: multiplayer.txt now says session: up
    and this machine: authority; blink, defensive ECM and offensive ECM all

  * [ ] Jam with ECM on an enemy contact: the log shows the game's jam order

    plainly that the effects are the host's to decide (the target is simulated

  * [ ] Stop jamming: the message says plainly that the host's jam task is its

  * [ ] ECM cones still draw on the client, from whatever jamming the host

WHAT TO SEND BACK

  * Which numbered checks failed  -  just the numbers, that is enough.
  * seapoweradvanced.log (mod folder) for anything that failed, and the
    matching LogOutput.log lines.

    both sides.
