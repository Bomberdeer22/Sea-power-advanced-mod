==============================================================================
TEST PLAN
==============================================================================

Run this once per game version, and after any change to HatchControl,
HatchMenu, TrafficGenerator or RouteFactory.

Version under test: 0.12.1. Mod id io.github.bomberdeer22.seapoweradvanced.

Read the log, do not guess. Everything below is confirmed by two files:

  BepInEx\LogOutput.log
      What it proves: BepInEx listed the plugin, Harmony patched the game.

  BepInEx\plugins\SeaPowerAdvanced\seapoweradvanced.log
      What it proves: The mod's own log. If this file exists, the code ran.

If seapoweradvanced.log is missing, nothing else in this plan can pass  -
stop and send SeaPowerAdvanced-diagnose.txt (from diagnose.cmd).

0. BEFORE THE FIRST TEST
------------------------

  * [ ] check-source.cmd says PASS. It costs a second and catches the
    using/type mistakes that otherwise show up as CS0246 two minutes into a
    build. build.cmd runs the same check as step [4/6]; it never blocks the
    build.

  * [ ] BepInEx + the Anchor Chain preloader in the game folder (run build.cmd
    once and it puts them there); the game does not say "The Anchor Chain
    preloader is not running!"
  * [ ] SeaPowerAdvanced.dll + _info.ini in BepInEx\plugins\SeaPowerAdvanced\
    (written by build.cmd, step [install])
  * [ ] No leftover copy in Sea Power_Data\StreamingAssets\SeaPowerAdvanced\
    -  a double install loads every patch twice
  * [ ] Game fully restarted after the build (code loads once per launch)
  * [ ] LogOutput.log open in a second window

1. LOAD
-------

In LogOutput.log, BepInEx's own banner should appear:

  * [ ] Loading [Sea Power Advanced 0.12.1]

Then the mod's own startup lines:

  * [ ] Sea Power Advanced: ================ Sea Power Advanced 0.12.1
    ================
  * [ ] Sea Power Advanced: Entry point:  BepInEx plugin
  * [ ] Sea Power Advanced: Settings: enabled=True includeGuns=False ...
  * [ ] Sea Power Advanced: Patched MapUnitViewModel.GetContextMenuItems.
  * [ ] Sea Power Advanced: Context menu patch is live (...)
  * [ ] Sea Power Advanced: Civilian traffic panel ready (F8 toggles it inside
    the mission editor).
  * [ ] Sea Power Advanced: Ready. Right-click a ship > Orders > Weapon
    hatches.
  * [ ] No Could not patch, no Startup failed

If Entry point: says AnchorChain mod, the DLL is being loaded from
StreamingAssets  -  that is the double-install case; remove that folder.

Anchor Chain's Workshop copy is optional: without it the build produces the
BepInEx-only plugin and the startup line reads Anchor Chain not installed -
building the BepInEx-only plugin. This is fine. Builds with Anchor Chain
installed also compile an AnchorChain mod entry point, which is unused on the
BepInEx route.

7. CIVILIAN TRAFFIC (MISSION EDITOR)
------------------------------------

This is the feature that has never run, so expect to find something here.
Press F8, then Check setup: traffic-report.txt in the mod folder now lists
every prerequisite with an ok/-- mark, so a failure points at one link instead
of the whole feature.

  * [ ] Open the mission editor on a new mission
  * [ ] Log reads Mission editor detected; the civilian traffic panel is
    available.
  * [ ] Press F8 -> a Civilian traffic window appears; drag it by the title
    bar
  * [ ] Classes: line shows non-zero counts, and the log reads Civilian
    catalogue: N civilian vessel class(es), M civilian aircraft class(es).
    (0/0 means nothing in this install is flagged civilian  -  send the log)
  * [ ] Press Draw zone, left-click 4-6 points around open sea, then Finish
    (or middle-click). Log reads Zone tool: polygon mode started. ...
  * [ ] The Zone: line shows the point count and an area in nm2
  * [ ] Set min/max ships to 2/4, planes to 0/0, press Spawn traffic
  * [ ] Log reads Civilian traffic: Added N ship lane(s) (up to 4 vessel(s) at
    a time) and 0 aircraft lane(s) ...
  * [ ] Save the mission, then play it: the ships appear inside the drawn
    area, not outside it
  * [ ] They keep coming back after finishing their run (_maxUnits is a
    concurrency cap, not a total)
  * [ ] Remove generated takes them back out; log reads removed N generated
    route(s).

Then repeat with planes set to 1/2 and ships 0/0.

  * [ ] Draw a zone that crosses land: units should stay off the land, or

  * [ ] Draw a tiny zone (a few km): the panel should refuse it, not spawn one

  * [ ] Reload the saved mission: does the traffic survive the round trip

9. WITH THE MULTIPLAYER MOD (OPTIONAL)
--------------------------------------

Only if SeapowerMultiplayer is installed. The mod finds it by itself;
multiplayer.txt in the mod folder is the file that answers everything below.

  * [ ] Single player: multiplayer.txt reads present: no (or present: yes,
    session: not up), and every feature behaves exactly as it did without it
  * [ ] seapoweradvanced.log gains one line: Multiplayer: no multiplayer mod
    or Multiplayer: multimod <version>, installed, no session up
  * [ ] Start hosting, open a mission: multiplayer.txt now says session: up
    and this machine: authority; blink, defensive ECM and offensive ECM all
    work as in single player
  * [ ] Join as the client: this machine: client
  * [ ] Sensors -> Radar blink: the start message says the half-cycle was
    raised to 12 seconds
  * [ ] Blink a ship and watch the radar: it goes on and off at ~12 second
    intervals, no rate-limited warnings in LogOutput.log from the multiplayer
    mod
  * [ ] Blink a ship you do not command: the blink stops itself within a few
    seconds and the log says the switch was refused or reverted. That is the
    expected behaviour, not a failure
  * [ ] Sensors -> Auto-ARM shutoff reads not available in multiplayer, and
    Defensive ECM reads the host runs missile defence in multiplayer
  * [ ] Lock with ECM on an enemy contact, then Jam now: the log reads jam
    order sent to the host, and the multiplayer mod's own log shows it applied
    the jam on the host
  * [ ] Stop jamming: the message says plainly that the host's jam task is its
    own and runs until it ends
  * [ ] ECM cones still draw on the client, from whatever jamming the host
    replicated in

WHAT TO SEND BACK
-----------------

  * Which numbered checks failed  -  just the numbers, that is enough.
  * seapoweradvanced.log (mod folder) for anything that failed, and the
    matching LogOutput.log lines.
  * hatch-report.txt for anything hatch-related that did not move.
  * For traffic: the ship class and mount for any hatch that did not move, and
    whether the units appeared in the right place, off the coast, or not at
    all.
  * In a multiplayer session: multiplayer.txt, plus the multiplayer mod's
    LogOutput.log lines for the same minute  -  a refused order is logged on
    both sides.

diagnose.cmd collects system, game folder, mod files, build logs and game logs
into one file. If in doubt, run it and send SeaPowerAdvanced-diagnose.txt.
