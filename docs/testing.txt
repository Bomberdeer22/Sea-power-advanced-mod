Read the log, do not guess. Everything below is confirmed by two files:

  BepInEx\LogOutput.log

    that otherwise show up as CS0246/CS0103 two minutes into a build: a

    never blocks the build.

    once and it puts them there); the game does not say "The Anchor Chain

    (written by build.cmd, step [install])
  * [ ] No leftover copy in Sea Power_Data\StreamingAssets\SeaPowerAdvanced\
    -  a double install loads every patch twice
  * [ ] Game fully restarted after the build (code loads once per launch)
  * [ ] LogOutput.log open in a second window

CHECKS THAT RUN WITHOUT THE GAME
--------------------------------

Three of them, and they are the gate before anything is handed over. They need
Python 3 and nothing else - no game DLLs, no compiler:

    python tools\check-source.py       :: the mistakes that have actually broken builds
    python tools\check-batch.py        :: the .cmd files: labels, blocks, stale %expansion%
    python tools\check-versions.py     :: the version agrees in all seven places it is written
    python tools\check-docs.py         :: every .txt twin still matches its Markdown

check-source.py is the one that grows: every time a build fails on something a
compiler sees and Python could have, a rule is added for it - and one rule is
there because of a download failure rather than a build one. No executable
bytes in the tree, in any form: a committed .exe/.dll/.zip/.msi fails the
check, so does any file whose first bytes are MZ whatever it is called, so
does any text carrying an encoded program header, and so does any batch or
PowerShell file that is not one of the repository's own tools. That rule
exists because 0.24.0's archive carried one compiled test fixture and every
browser refused to download it - and because encoding that fixture as text did
not help: the archive still held a program in disguise, and the download was
still refused. The fixture now lives nowhere in the tree. selftest.py --fetch
downloads it, checks its SHA-256 against the constant in the script, and
writes it to testdata/ locally (never committed); without it the selftest
skips and exits 2, so the rest of the gate still runs. The newest rule covers
the imports of BCL types - List, Dictionary, HashSet, IEnumerable,
StringBuilder, Regex, BindingFlags, Path and the rest - because 0.24.0 shipped
a file that used List<> and Dictionary<> without importing the namespace that
declares them, and that cost a build. --fix puts the missing line back by
itself.

All four run on every push (.github/workflows/checks.yml). They do not prove
the mod compiles - only the compiler against your own game DLLs can do that -
they prove the things a compiler does not look for. What has to be true before
a release is tagged is in releasing.md.

WHAT TO SEND BACK
-----------------

  * Which numbered checks failed  -  just the numbers, that is enough.
  * seapoweradvanced.log (mod folder) for anything that failed, and the
    matching LogOutput.log lines.
  * hatch-report.txt for anything hatch-related that did not move.
  * In a multiplayer session: multiplayer.txt, plus the multiplayer mod's
    LogOutput.log lines for the same minute  -  a refused order is logged on
    both sides.

diagnose.cmd collects system, game folder, mod files, build logs and game logs
into one file. If in doubt, run it and send SeaPowerAdvanced-diagnose.txt.
